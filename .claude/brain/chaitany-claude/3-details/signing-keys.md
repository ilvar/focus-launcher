# Tier 3 · Signing keys

## The release key (created 2026-09-19 for the public download)
- A PKCS12 keystore kept **outside the repo**, readable by the owner only. Where it is, its alias
  and its password are in **`keystore.properties`** at the repo root (git-ignored, mode 600).
- RSA 4096, valid until 2056. The certificate names the project and the domain, not a person, on
  purpose.
- Certificate SHA-256 (public information: anyone can read it from the APK; useful to confirm an
  APK is genuine):
  `52:6A:00:B8:74:66:0A:F4:26:66:99:D5:79:5A:45:7D:DE:BE:95:8A:78:48:48:20:FA:C4:B6:1B:2A:48:52:A2`
- The password was generated with `openssl rand` straight into that file and has never been
  displayed or logged. **Keep it that way**: pass it to tools with `-storepass:file` or process
  substitution, never as an argument, never `cat` the file. To learn the keystore's location
  without seeing the password: `grep '^storeFile' keystore.properties`.
- If the keystore or its password is lost, no update can ever be installed over a published build.
  The owner was told to back up both. There is no copy anywhere else.

## How Gradle uses it
`app/build.gradle.kts` loads `keystore.properties` if present into `signingConfigs["dist"]`;
build type `dist` = `initWith(release)` + that config. Without the file, `assembleDist` cannot
sign: that is intended. Verify a build:
```bash
APKSIGNER="$ANDROID_HOME/build-tools/36.0.0/apksigner"      # ANDROID_HOME = sdk.dir in local.properties
$APKSIGNER verify --print-certs app/build/outputs/apk/dist/app-dist.apk | grep "certificate DN"
```
Signature scheme v2 only (minSdk 26 ≥ 24, so v1/JAR signing is unnecessary).

## The debug key, and the owner's phone
`release` and `debug` builds are signed with Android's debug key (generated by the SDK, unique to
the development machine). That is what runs on the owner's phone: it lets optimized builds install
over debug builds and keep his data. It must **never** be published.
Consequence: the public `dist` APK cannot be installed over what is on his phone. Moving his phone
to `dist` means uninstalling once, which resets Focus's settings and its grants (default launcher,
usage access, calendar). Offered; not done; **never uninstall without asking**. A future
"export / import settings" feature would make that migration painless.
